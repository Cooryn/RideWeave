# RideWeave 0.2.1

Windows 个人骑行轨迹管理应用。Tauri 2 + React + TypeScript + MapLibre GL JS / OpenFreeMap（OpenStreetMap 数据） + SQLite。无账户、无云同步，真实数据为空时展示空状态，不附带虚构骑行记录。

## Windows 开发与运行

环境：Node.js 22.13+（推荐 24 LTS）、Rust stable MSVC、Visual Studio 2022 Build Tools（“使用 C++ 的桌面开发”及 Windows SDK）、Microsoft Edge WebView2 Runtime。SQLite 文件测试使用 Node 内置的 `node:sqlite`。

```powershell
npm ci
rustup toolchain install stable --profile minimal
npm run tauri dev
```

`npm run dev` 仅启动浏览器 UI 预览，不提供数据库或导入功能，避免误以为数据已保存。桌面入口使用 `npm run tauri dev`。

## 导入和使用

1. 从 Apple 健康导出数据并解压，找到 `workout-routes` 中的 GPX 文件（具体目录取决于导出版本）。本版不解析 ZIP 或健康 XML，也不自动识别运动类型，请选择骑行文件。
2. 点击右上角“导入 GPX”，按 Ctrl / Shift 多选；支持每个不超过 50 MB 的文件。
3. 导入结果显示新增、重复和失败数量，每个失败文件有单独原因；单个失败不影响其他文件。
4. 骑行路线显示原始 GPX 并自动闭合暂停缺口，骑行热区将经过的道路归并居中并显示次数渐变。点击路线或记录查看详细数据。眼睛按钮切换路线显示。“全部轨迹”恢复所有路线并适配地图范围。
5. 在详情中修改名称；最近骑行、历史记录每行右侧的垃圾桶按钮以及详情页均可删除记录。点击后显示包含记录名称的确认提示，确认保存成功后同步更新列表、统计与地图；失败保留记录并可重试。删除数据库中的轨迹和原始 GPX，不删除源文件。

## 数据规则

- 距离：WGS84 经纬度的大圆距离（平均地球半径 6371.0088 km）累计，**不跨 trkseg 或 route 分段连接**。道路贴合仅用于地图显示，不改变原始距离；不提供去重道路里程。
- 时间：所有轨迹点具有有效且非倒序的带时区时间时，以首尾时间差计算经过时间，含停留。骑行详情不足一小时仅显示分钟（如 `12min`），满一小时显示 `2h 15min`，分钟向下取整；时间不完整、倒序或总时长为零则显示“暂无数据”。
- 平均速度：GPS 距离 ÷ 经过时间，不是移动速度。
- 日期：首个有效轨迹时间；本月统计使用系统本地时区。没有日期的记录不计入本月。
- 累计时间只合计有有效时间的记录，并提示缺失记录数。
- 去重：分段 GPS 坐标及标准化时间的 SHA-256，不受文件名、XML 排版或轨迹名称影响；同一路线不同日期保留。无时间且坐标完全相同的文件视为重复。
- 支持 GPX trk/trkseg 和 rte，保存各点海拔（如有）。纯 waypoints、少于两个连续有效点、无效坐标、损坏 XML 会报错，不用虚构值补齐。

## 数据保存和备份

SQLite 由 Tauri SQL 插件保存在 Windows 应用配置目录：

```text
%APPDATA%\com.rideweave.desktop\rideweave.db
```

每条记录保存解析后的点、统计字段以及完整原始 GPX。数据库通过版本化迁移创建，重启自动加载。关闭应用后备份整个该目录（如有 SQLite 附属文件，一并复制）。主题偏好保存在 WebView 本地存储。

底图使用 OpenFreeMap 的在线矢量地图，无需填写 Key。深浅主题基于 dark / liberty 样式保留地平线 6 风格外观：灰绿色地物、浅色路缘与灰色路面，暖橙色小路及桥隧分层；仅调整绘制样式，使用供应方原始数据源和道路几何，双向车道保持分开，不改写底图瓦片。骑行线另行叠加到道路中间。地图服务会接收到地图范围、样式、字体等资源请求；GPX 不上传。需要 WebGL 支持。断网仍可导入和管理记录；样式加载失败时使用纯背景，已缓存的道路仍可用于居中骑行线，并提供重试按钮。本版不提供离线底图库或批量下载。

## 骑行路线与骑行热区

地图提供“骑行路线 / 骑行热区”。当前应用会话内会记住所选模式，切换侧栏页面后返回地图时继续使用之前的模式。骑行路线显示原始 GPX 的位置和形状，普通路线为亮青色、所选路线为亮黄色；仅在识别的暂停处补连。骑行热区使用归并居中的道路参考线，按累计经过次数保留热度渐变。两种模式都使用相同的圆角实线、缩放线宽及细深色描边，便于在深浅底图上识别。保存的原始 GPX、里程和时间统计不变。

- **日夜一致**：白天和黑夜共用同一份在线地图模板及道路图层，仅切换底图配色。骑行线的颜色、线宽、圆角、描边与热区渐变均不随主题改变，离线回退也使用同样的骑行线样式。
- **原始道路几何与驾驶地图外观**：原始地图的双向车道、辅路和桥隧分别保留，只用地平线 6 风格的配色、路缘和路面重新绘制。底图不经过车道合并；用于 GPX 匹配的道路数据在本地另行处理，生成两侧车道中间的参考线，只影响骑行叠加层。
- **道路接缝**：铺装道路的阴影、路缘和路面使用平齐端头，弯道保留圆角，避免分段绘制的桥梁或隧道在相接路面上形成白色胶囊状封口。桥隧仍按原有层级绘制；单笔小路线条保持圆头，不改动道路几何或 GPX 数据。
- **居中合并（热区及暂停道路补线）**：通过固定 14 级道路数据识别双向分隔车道，建立共享参考线，再将骑行点匹配到参考线上；两侧车道上的经过次数累计到同一条线，同次骑行的往返和重复经过分别计数。居中结果不随地图主题或显示缩放重新改变。
- **合并边界**：仅归并同等级、同桥隧层级、方向相反、近似平行且间距约 3—32 米的重叠车道，随路口移动匹配模型中的相接支路；辅路、匝道、环岛和不同层级道路分开处理。同一桥梁或隧道的一侧缺少层级标记时，仅在对向车道给出唯一层级、几何及道路身份均相容时补足内部匹配层级；明确标注不同层级或出现冲突时保持分开，不修改原始瓦片。道路名称或编号冲突、没有身份信息的普通街道、多个同样合理的候选和其他无法识别的情况不强行合并。因此这是基于公共瓦片的几何估算，复杂路口、缺失道路和无法区分的平行道路仍可能产生误差。
- **路口整理**：先在配对车道之间传播全部路口切点，再生成中心线，避免后来发现的支路停在未切开的线段旁。对已确认配对车道附近、由原有道路连接围成的短小分隔带和转向闭环，收拢为共享路口并移动相接道路；限制闭环及整个合并区域的大小，不仅凭距离吸附。带环岛标记或原本闭合的道路受到保护，辅路、匝道及不同桥隧层级不参与闭环收拢。
- **连续匹配**：按 GPX 顺序，以约 12 米间隔选取观测点并使用较长方向基线，结合 45 米内的多个道路候选和有界路网路径做序列匹配；处理弯道、T 字路口和瓦片边界；对同层级、以明显夹角接入的道路端点，容忍 1.5 米以内的瓦片坐标误差，平行道路及普通内部顶点仍使用严格阈值；使用后续轨迹回溯选择前面的连续路径，减少在平行主路、辅路和自行车道之间的错误切换；终点分叉不确定时保留已确认的共同前缀。普通观测匹配仍在分段和超过 300 米的跳点处断开，满足暂停条件的缺口另行沿道路推测补连。缺失道路、无法区分的平行道路及不合理绕行不强行连线；复杂路口或定位漂移仍可能产生误差。
- **自动暂停补连**：仅处理同一条骑行记录中相邻片段。先按端点直线距离和时间识别暂停候选：距离不超过 2 公里、时间正序且间隔不超过 2 小时，500 米以内的候选直线速度上限为 60 km/h；超过 500 米时上限为 35 km/h，至少暂停 60 秒，前后各 30 秒内至少 4 个连续点、覆盖至少 5 秒且净移动至少 10 米，净移动不少于累计路程的 60%，排除起步定位跳变和原地抖动。没有端点时间时仅尝试 30 米以内的缺口，时间缺失一侧或倒序则不补。同一分段中达到 30 秒且位移达到 15 米的采样中断也会检测。识别暂停后，优先使用已匹配的起终道路，方向不足时将端点吸附到 45 米内最近的道路，用 Dijkstra 在已加载路网中按长度求最短路径；存在多个近似备选、路径绕行较长或沿路速度超限都不再拒绝补连。原始路线在道路尚未加载、不连通或端点附近没有道路时直接连接暂停两端，不显示补连提示或道路重试按钮；热区只显示已有道路上的补线。不跨不同记录连接，不跳过无效点或孤立单点片段。补线路径按顺序单独保留，连接原始 GPS 两端，不挪动已记录的点；在骑行路线、热区和所选记录中均按正常实线显示，不增加独立补连图例。
- **道路重合度**：按实际匹配到同一道路片段的累计经过次数统计；同次骑行去一次、返回一次计为 2 次，多圈骑行逐圈累计，局部折返只增加实际重走部分的次数。不同记录的经过次数相加，GPS 采样点与瓦片重复副本不额外增加计数；骑行记录 ID 仍保持唯一，用于路线选择。暂停补线保留内部来源标记，不增加实际经过次数，也不计入原始距离；热区中按至少 1 的色阶绘制补线，并与相邻路段平滑过渡，实际计数保持不变。图例显示“1—渐变色条—10+”；加载及失败提示在图例上方排列。隐藏、显示、删除和新增记录后重新计算。
- **沿道路渐变**：蓝（1 次）、青（2 次）、绿（3 次）、黄（5 次）、橙（8 次）、红（10 次及以上）。在重合度变化处沿道路最多 10 米做颜色过渡，原始计数保持不变。线条无模糊、光晕或径向扩散，缩放不改变重合度。热区 GeoJSON 禁用几何简化，避免缩小时把渐变短线段当作小要素过滤而产生断线。
- **自动加载道路**：按轨迹走廊请求 OpenFreeMap 的 14 级 transportation 道路瓦片，并为可信的暂停候选补充 45—150 米的走廊，长暂停扩展至最多 450 米，供沿道路寻找连接。先缓存原始道路，再汇总所有已加载瓦片统一建立居中匹配路网；按道路 ID 识别缓冲区中的同一道路，去除重复边，并传播已归并区间，避免不同裁切副本留下第二条车道或路口折线。独立于可见地图缩放，无需先放大。并发最多 4 个请求，每次最多 256 块，超出范围或加载失败会标示数据不完整，可隐藏部分记录缩小计算范围。道路随可见记录自动加载，移除单独的“重试道路”按钮。
- **隐私与离线**：请求仅为公共道路瓦片 URL，服务可见瓦片范围；不上传 GPX、时间或轨迹点列表。本次应用会话中最多缓存 384 块已加载道路，断网可复用；未缓存道路无法生成热区，热区模式会提示道路不可用；原始骑行路线及其暂停端点闭合可离线显示且不弹出道路提示，已保存记录仍可管理。不是完整离线路网库，不持久化匹配结果。
- **路线聚焦**：点击记录或热区后显示所选记录的原始 GPX 路线及暂停补线，并自动居中；关闭详情恢复之前视图，点击“骑行热区”返回渐变热区。“全部轨迹”恢复所有记录。原始距离、时间与 GPX 不受影响。

实现参考：[MapLibre 线条图层](https://maplibre.org/maplibre-style-spec/layers/#line)、[OpenMapTiles transportation 数据结构](https://github.com/openmaptiles/openmaptiles/blob/master/layers/transportation/transportation.yaml)。41 项自动化测试通过，覆盖路网连续性、重复计数、沿线渐变、瓦片加载/缓存/失败重试/取消、6–16 级实际 GeoJSON 瓦片切分连续性、路线聚焦，以及列表删除的取消、失败重试和状态同步。2026-10-27 前端生产构建及包含本次调整的 Windows x64 NSIS 安装包构建成功。已用公开道路瓦片及合成轨迹检查解码，并对用户提供的真实 GPX 在本地进行了修复前后连续性对比。用户 GPX、位置坐标及诊断缓存不纳入仓库。新增回归覆盖平行路的后续观测消歧、短距离方向抖动和终点不确定时的前缀保留。尚未进行真实 GPX 桌面端到端或 GPU 视觉验收。

### 界面与窗口

默认使用运动风格深色外观：近黑背景、炭灰圆角卡片和彩色指标；设置中可切换浅色模式。字体优先使用系统无衬线字体，Windows 使用 Segoe UI Variable / 微软雅黑 UI，无需下载字体。

桌面窗口使用应用内标题栏：拖动顶部空白区域移动窗口，双击拖动区域最大化或还原，右上角按钮负责最小化、最大化或还原和关闭。内容区与记录列表使用细窄主题滚动条，支持滚轮与拖动。浏览器预览不显示桌面窗口控制按钮。更换系统窗口装饰需要重新启动桌面应用。

发布构建必须启用 `custom-protocol`，将前端资源内嵌到程序中。禁止直接将不带此特性的 `cargo build --release` 产物打包，否则程序会连接开发服务器 localhost:1420。项目已添加编译保护以阻止此类发布构建。


浅色外观与深色外观共享运动指标配色语义，使用冷灰背景、白色卡片和适合浅底阅读的深色指标。应用内品牌标识直接引用 `src-tauri/icon.svg`，桌面 ICO 与其他尺寸图标由同一源文件生成，保持荧光绿圆底与黑色骑行人物一致。

Windows 图标资源由 `build.rs` 显式跟踪 `icons/icon.ico` 的变更，以免增量构建复用旧图标。更换图标后应检查最终 EXE 提取出的图标，不能仅检查 SVG 或 PNG 源文件。
